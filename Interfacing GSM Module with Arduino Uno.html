Interfacing GSM Module with Arduino Uno

A practical learning guide to connect a GSM modem to an Arduino, communicate using AT commands, and send an SMS alert. Includes wiring, sample code, troubleshooting, revision notes, interview questions, and interactive quizzes.

1. Introduction and learning objectives

A GSM (Global System for Mobile Communications) module is a cellular communication modem that lets a microcontroller exchange information over a mobile network. With an Arduino Uno, it can send SMS messages, make calls, or exchange data, depending on the modem and network support.

How it works

The Arduino sends serial commands called AT commands to the modem. The modem uses a SIM card and cellular network to perform the requested action.

Learning objectives

  • Identify the hardware and serial interface.
  • Connect TX/RX and power safely.
  • Use basic AT commands.
  • Upload code to send an SMS.
  • Test and debug the link.

Prerequisites

Basic Arduino programming, digital voltage levels, UART serial communication, and familiarity with a SIM card and cellular coverage.

Network compatibility: Many classic SIM800/SIM900 modules use 2G GSM. In some regions, 2G service has been retired or is unavailable. Confirm local network availability and your module's supported bands before buying or testing. A 4G/LTE module requires its own compatible wiring, power supply, and commands.

2. Hardware and circuit connections

Example below assumes a SIM800/SIM900-style UART GSM breakout and Arduino Uno. Pin labels and power requirements differ between breakout boards, so follow the exact module datasheet.

Important power and logic-level safety: Do not assume the GSM board can be powered from the Uno's 5 V pin. Cellular modems draw large, brief current peaks; inadequate power causes resets and failed SMS sending. Use the board's recommended regulated supply. Some bare modules use low-voltage UART logic and are not 5 V tolerant; use a suitable level shifter or interface board. Check the exact breakout documentation before wiring.

3. Working principle: step by step

  1. Insert an active SIM card; disable its PIN lock if the program does not handle PIN entry.
  2. Connect the antenna and provide the recommended supply.
  3. Arduino opens a UART serial link to the GSM modem.
  4. Arduino sends AT; modem should reply OK.
  5. Arduino configures SMS text mode using AT+CMGF=1.
  6. Arduino sends AT+CMGS="+countrycode-number".
  7. After the modem prompts with >, Arduino sends the message and ASCII Ctrl+Z (decimal 26).
  8. The modem submits the SMS to the network and returns a result such as +CMGS: ... followed by OK if successful.
Arduino → Modem

AT commands over UART TX.

Modem → Arduino

Replies and status messages over UART RX.

Modem ↔ Network

Radio link sends the SMS through the mobile network.

UART cross-connection rule

TX connects to RX, and RX connects to TX. UART is asynchronous serial communication; both devices must use compatible baud rates and logic levels.

5. Arduino program: send an SMS

This example uses SoftwareSerial on pins 10 and 11. Replace the phone number with the recipient's number in international format. Confirm that your modem supports the selected serial baud rate.

#include <SoftwareSerial.h>

// Arduino RX, TX. Cross-connect to modem TXD, RXD.
SoftwareSerial gsm(10, 11);

const char phoneNumber[] = "+12345678900"; // Replace with recipient number

void setup() {
  Serial.begin(9600);   // USB serial monitor
  gsm.begin(9600);      // Common example baud; verify your modem
  delay(1500);

  Serial.println("Starting GSM SMS test...");
  gsm.println("AT");
  delay(1000);
  showModemReply();

  gsm.println("AT+CMGF=1"); // SMS text mode
  delay(1000);
  showModemReply();

  gsm.print("AT+CMGS=\\"");
  gsm.print(phoneNumber);
  gsm.println("\\"");
  delay(1000); // Wait for the '>' prompt on a simple demo

  gsm.print("Hello! SMS sent using Arduino Uno and GSM.");
  gsm.write(26); // Ctrl+Z submits the SMS
  delay(5000);
  showModemReply();
}

void loop() {
  // Forward any new modem replies to the Serial Monitor.
  while (gsm.available()) {
    Serial.write(gsm.read());
  }
}

void showModemReply() {
  unsigned long start = millis();
  while (millis() - start < 1500) {
    while (gsm.available()) {
      Serial.write(gsm.read());
    }
  }
}
Educational example, not production-grade code: Fixed delays are simple for a lab demonstration but do not robustly verify the > prompt, network registration, or SMS submission. For reliable projects, parse modem responses with timeouts and error handling. Some modules use a different default baud rate or need explicit power-on control.

Code explained

  • SoftwareSerial gsm(10, 11): creates a serial connection using Arduino pins 10 (RX) and 11 (TX).
  • gsm.begin(9600): sets the serial speed; it must match the modem.
  • AT+CMGF=1: chooses text mode for SMS.
  • AT+CMGS: starts the SMS sending procedure.
  • gsm.write(26): sends Ctrl+Z, telling the modem the message is complete.

6. Testing procedure and troubleshooting

  1. Check the module supply voltage and current rating against its datasheet.
  2. Check SIM activation, PIN status, antenna, and cellular coverage.
  3. Upload the sketch and open Serial Monitor at 9600 baud.
  4. Look for modem responses to AT and AT+CMGF=1.
  5. Verify registration with the modem's supported registration command.
  6. Confirm the recipient number format and check for an SMS submission response.

7. Applications and engineering relevance

Applications

  • SMS alerts for home/security alarms.
  • Remote monitoring of water tanks, temperature, or equipment status.
  • Vehicle tracking and alert systems (with suitable GPS hardware).
  • Industrial fault notifications and remote telemetry.
  • Smart agriculture alerts for pumps or sensors.

Design considerations

  • Network availability and supported radio bands.
  • Peak current, supply noise, and decoupling.
  • UART voltage compatibility and baud rate.
  • Message delivery delays and error handling.
  • SIM plan, privacy, security, and recurring costs.

8. Core electronics interview questions

1. What is a GSM module?

A cellular modem that lets a controller communicate over a mobile network using interfaces such as UART and commands such as AT commands.

2. Why are TX and RX crossed?

One device's transmit output must feed the other device's receive input, so Arduino TX goes to modem RX and modem TX goes to Arduino RX.

3. What is an AT command?

A text command used to configure and control a modem. AT is commonly used as a basic communication test.

4. Why might a GSM module need a separate supply?

Its transmit bursts can draw high peak current. A weak supply can cause voltage drops, resets, and failed network operations.

5. What does AT+CMGF=1 do?

It selects SMS text mode on modems that support this command. PDU mode is another SMS representation.

6. Why is Ctrl+Z sent after the SMS body?

ASCII decimal 26 signals the end of the message body and requests submission.

7. How do you check signal quality?

Use AT+CSQ. Interpret its result according to the modem documentation; RSSI 99 generally indicates unknown or undetectable.

8. Why is a common ground important?

It provides a shared reference for UART signal voltages when the devices use separate supplies.

9. The module responds to AT but cannot send an SMS. What do you inspect?

SIM readiness, network registration, signal, SMS mode, phone-number format, message prompt handling, and the final modem error response.

10. Can every GSM module connect directly to Arduino 5 V logic?

No. UART logic thresholds differ. Check the board documentation and use level shifting if the modem RX input is not 5 V tolerant.

11. What is the difference between UART and GSM?

UART is a local serial communication interface between devices; GSM is a cellular radio system/network technology. UART can carry AT commands to the modem.

12. How would you make the SMS code more robust?

Wait for and parse expected responses, use timeouts, verify registration, retry carefully, log error codes, and avoid assuming a fixed delay means success.

10. GATE-style practice (original questions)

These are original practice questions, not claimed to be official previous-year questions.

Q1 • Easy — Which command checks whether a modem responds?

Answer: AT. A responding modem commonly returns OK.

Q2 • Easy — For Arduino SoftwareSerial(RX=10, TX=11), where should pin 10 connect?

Answer: Modem TXD. Arduino's receive pin must receive the modem's transmit data.

Q3 • Moderate — Which command selects SMS text mode on a compatible modem?

Answer: AT+CMGF=1. The value 1 selects text mode; 0 generally selects PDU mode.

Q4 • Moderate — What character commonly submits an SMS after the body?

Answer: Ctrl+Z (ASCII 26). It marks the end of the message body for submission.

Q5 • Moderate — A modem resets during transmission although UART wiring is correct. What is a prime suspect?

Answer: Insufficient peak-current capability or supply voltage drop.

Q6 • Difficult — Why must a designer check module logic voltage?

Answer: The modem UART pins may not tolerate Arduino Uno's 5 V output; exceeding the input rating can damage the module.

Q7 • Moderate — Does AT+CSQ itself register the modem on the network?

Answer: No. It queries signal quality; registration is a separate network state.

Q8 • Difficult — Why is waiting a fixed 1 second after every command not robust?

Answer: Response times vary. Parse expected prompts and results with timeouts rather than assuming the operation completed.

Q9 • Moderate — What is required if the modem uses a retired cellular technology in your area?

Answer: Use a compatible modem/network technology and supported bands; code changes alone cannot restore unavailable network service.

Q10 • Difficult — Why can an SMS command return an error even when AT communication works?

Answer: The serial link may work while SIM readiness, registration, signal, SMS configuration, recipient number, or operator service is not valid.

11. Quick revision sheet

Must remember

  • UART wires cross: Arduino TX → modem RX; modem TX → Arduino RX.
  • Use common GND with separate supplies.
  • Check modem power and logic voltage in its datasheet.
  • AT → communication check.
  • AT+CMGF=1 → SMS text mode.
  • AT+CMGS="number" → start SMS.
  • Ctrl+Z / ASCII 26 → submit message.

Frequent mistakes

  • Powering a modem from an unsuitable Arduino pin.
  • Connecting TX to TX or RX to RX.
  • Forgetting the antenna or SIM/network compatibility.
  • Using the wrong baud rate or number format.
  • Assuming OK for AT means SMS delivery is guaranteed.
  • Ignoring that 2G coverage varies by region.
